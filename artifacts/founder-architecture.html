Layer 4 — Tenant Containers (One per Customer · Ports 4100–4199)
Layer 4 · Tenant Containers

Each tenant gets an isolated Docker container on the client runtime VPS. The provisioner creates /srv/sync360/runtime/tenants/{slug}/ locally, syncs it over SSH, installs a Caddy site config, then starts the container. After go-live, workspace markdown files are synced independently without touching credentials.

runtime/{slug}/
  • .env — tenant slug, port, workspace URL
  • metadata.json — tenant/server/job snapshot
  • config/openclaw.json — gateway, channels, LiteLLM (immutable post-provision)
  • compose.yaml — container definition (immutable post-provision)
  • data/ — OpenClaw persistent data
  • logs/ — container logs
.openclaw/workspace/
  • IDENTITY.md — who the agent is
  • SOUL.md — values and principles
  • USER.md — user instructions
  • BOOTSTRAP.md — init context + capabilities
  • PROFILE.md — business info, hours, services
  • HEARTBEAT.md — core rules, tone, escalation
  • memory/*.md — session conversation logs (read by control plane)
Sync boundary (critical)
  • syncRuntime() — full sync; used for initial provisioning only
  • syncWorkspaceFiles() — workspace markdown only; used by goLive() and profile sync
  • putFile() — single file write; used by configureChannel()
  • Never call syncRuntime() post-provision — overwrites credentials
Container lifecycle
  • Started by OpenClawProvisioner via SSH
  • restart: unless-stopped policy
  • Readiness: private /readyz (45s) then public /login (120s)
  • Admin: start/stop/restart via panel
  • Channel config change → putFile + restart (no reprovision)
  • Telegram polling mode — no webhook required

Full Provisioning Flow (Signup → Live Workspace)
1
Signup form submitted
RegisterController validates → DB transaction: User + Tenant (pending) + BusinessProfile + BusinessProfileFiles + ProvisioningJob (queued). ServerPlacementService selects VPS with spare capacity. Increments server.current_clients. Dispatches ProcessTenantProvisioning after commit. Redirects to /tenant/setup.
RegisterController → ServerPlacementService → ProcessTenantProvisioning::dispatchAfterCommit()
2
Queue worker picks up job → provisioner starts
ProcessTenantProvisioning resolves OpenClawProvisioner via DI. Marks job running, marks tenant provisioning.
ProcessTenantProvisioning → OpenClawProvisioner::provision()
3
Port allocation + LiteLLM tenant key
TenantRuntimeService allocates next free port (4100–4199 unique per server) and generates workspace URL ({slug}.workspace.sync360.co.nz). LiteLlmTenantKeyService creates a virtual API key for this tenant with plan-appropriate budget cap.
TenantRuntimeService::allocatePort() · LiteLlmTenantKeyService::ensureTenantKey()
4
Local runtime staging
Scaffolds runtime/tenants/{slug}/ from templates/tenant/. Writes: .env (port, slug, workspace URL), metadata.json (tenant/server/job snapshot), config/openclaw.json (gateway + agent + LiteLLM model config), compose.yaml (tenant container definition). Creates .openclaw/workspace/ directory.
TenantRuntimeService::prepareRuntime() → OpenClawProvisioner writes 4 files
5
Sync to remote VPS + Caddy
SshDockerComposeRunner::syncRuntime() rsyncs full local staging to /srv/sync360/runtime/tenants/{slug}/ on client VPS. Writes {slug}.caddy to /etc/caddy/sites/ via putFile(). Runs caddy reload. Subdomain now routes to the allocated port.
SshDockerComposeRunner::syncRuntime() + putFile() + runCommand("caddy reload")
6
Container started → two-stage readiness
docker compose up -d on client VPS via SSH. Stage 1: poll private 127.0.0.1:{port}/readyz on VPS via SSH-tunnelled curl (timeout 45s). Stage 2: poll public HTTPS {slug}.workspace.sync360.co.nz/login directly (timeout 120s). Both must pass.
SshDockerComposeRunner::up() + waitForHttpReady()
7
Mark ready + send workspace-ready email
Tenant marked ready. ProvisioningJob marked completed. WorkspaceReadyEmailService sends HTML+text email via Brevo with workspace URL + initial credentials. Customer's /tenant/setup polling auto-redirects to workspace-ready screen.
WorkspaceReadyEmailService::send() → Brevo API
8
Customer completes onboarding → go-live
Customer works through 6-step wizard. On go-live: TenantAgentSyncService::goLive() generates 6 markdown identity files (IDENTITY/SOUL/USER/BOOTSTRAP/PROFILE/HEARTBEAT), writes to .openclaw/workspace/, calls syncWorkspaceFiles() ONLY (never syncRuntime — would overwrite credentials), restarts container. Agent is now live with business personality.
OnboardingController::goLive() → TenantAgentSyncService::goLive() → syncWorkspaceFiles() + restart
