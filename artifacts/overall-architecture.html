Layer 4 — Tenant Containers (One per Customer · Ports 4100–4199)
Layer 4 · Tenant Containers

Each tenant gets an isolated Docker container on the client runtime VPS. The provisioner creates a /srv/sync360/runtime/tenants/{slug}/ directory with all config, syncs it over SSH, installs a Caddy site config, then starts the container pointing to that directory.

runtime/{slug}/
  • config/ — .env + metadata.json + openclaw.json
  • compose.yaml — tenant-specific docker compose
  • data/ — persistent tenant data
  • logs/ — container logs
  • workspace/ — OpenClaw workspace dir
metadata.json
  • tenant_id (ULID)
  • business_name, slug
  • industry, skill_pack
  • assigned_port
  • workspace_url
Container lifecycle
  • Started by OpenClawProvisioner via SSH
  • restart: unless-stopped policy
  • Readiness: polls GET /readyz (loopback + public)
  • Admin: start/stop via panel
  • Status in DB: Pending → Provisioning → Ready
Infrastructure drivers
  • SshDockerComposeRunner (prod) — 321 lines
  • LocalDockerComposeRunner (dev) — 167 lines
  • Swapped via SYNC360_INFRASTRUCTURE_DRIVER env
  • DockerComposeRunner contract: 9 methods

Full Provisioning Flow
1
Signup form submitted
RegisterController validates → DB transaction: User + Tenant (pending) + ProvisioningJob (queued). ServerPlacementService selects VPS with spare capacity. Increments server.current_clients. Dispatches job to Redis queue. Redirects to /tenant/setup.
RegisterController → ServerPlacementService → ProcessTenantProvisioning::dispatch()
2
Queue worker picks up job
ProcessTenantProvisioning loads Tenant + ProvisioningJob from DB. Resolves TenantProvisioner via DI (openclaw driver in prod, local driver in dev). Marks job running, marks tenant provisioning.
ProcessTenantProvisioning → OpenClawProvisioner::provision()
3
Port + URL allocation
TenantRuntimeService scans existing tenants on the server, finds next free port in 4100–4199 (unique per server constraint). Generates workspace URL: {slug}.workspace.sync360.co.nz. Saves to tenant record.
TenantRuntimeService::allocatePort() → ::generateWorkspaceUrl()
4
Local runtime staging
Generates runtime/tenants/{slug}/ locally. Copies templates. Writes .env (port, business name, skill pack, industry), metadata.json, config/openclaw.json, and compose.yaml for the tenant container.
TenantRuntimeService::scaffold() → 4 files written
5
Sync to remote VPS
SshDockerComposeRunner::syncRuntime() — rsync local staging to /srv/sync360/runtime/tenants/{slug}/ on client VPS over SSH. Cleans stale files from any previous failed attempt first.
SshDockerComposeRunner::syncRuntime() (321 lines)
6
Caddy site config installed
SCP writes {slug}.caddy to /etc/caddy/sites/ on client VPS. Runs caddy reload over SSH. Subdomain {slug}.workspace.sync360.co.nz now routes to the allocated port.
SshDockerComposeRunner::putFile() + runCommand("caddy reload")
7
Container started
docker compose up -d on client VPS via SSH. Container starts on the allocated port using the synced compose.yaml. OpenClaw image pulled if not cached.
SshDockerComposeRunner::up() → docker compose up
8
Readiness polling (two-stage)
Stage 1: Poll 127.0.0.1:{port}/readyz on client VPS via SSH-tunnelled curl (timeout 45s). Stage 2: Poll public HTTPS URL {slug}.workspace.sync360.co.nz/readyz directly (timeout 120s, poll every 1500ms). Both must pass before continuing.
OpenClawProvisioner → SshDockerComposeRunner::waitForHttpReady()
9
Mark ready + send email
Tenant marked ready. ProvisioningJob marked completed. WorkspaceReadyEmailService sends HTML+text email via Brevo with workspace URL + initial credentials decrypted from job payload. UI polling auto-redirects customer to workspace-ready screen.
WorkspaceReadyEmailService::send() → Brevo API

Remaining Gaps — Prioritised
Priority Gap Description Impact
P1 Stripe billing No payment gate — trial never expires, no subscription. Stripe Checkout + webhook for payment-triggered provisioning, trial enforcement, and plan upgrades is the next revenue-critical build. Blocks monetisation
P1 Channel connection wizard After workspace is ready, customers have no in-app flow to connect WhatsApp or email to their OpenClaw instance. Without this, the digital employee can't receive any messages. This is the key activation gap. Blocks activation
P2 Skill Registry + Deployer skill_pack is currently free text. The proven skills (email triage, booking, quotes/invoices) need to be packaged as versioned bundles with a SkillDeployerService to push them into containers at provision time or on upgrade. Core product moat
P2 LiteLLM proxy No per-tenant LLM cost tracking or model switching. Add LiteLLM as a shared service on client VPS with per-tenant virtual API keys. Required before enforcing any usage-based plan limits. Cost control + upsell
P2 Container health monitoring Containers have restart: unless-stopped but no proactive watchdog. No alerting if a container crashes silently. Recommend heartbeat polling from the control app with admin notification. Reliability
P3 SSH key auth Password-auth SSH via sshpass works but is not production best practice. Migrate to key-based auth — the Server model already has ssh_auth_mode = key support ready. Security hardening
P3 Calendar integrations Google Calendar / Cal.com config hooks needed by the Booking skill. Per-tenant OAuth or API key at provisioning time. Not yet built. Booking skill activation
P3 DNS automation Wildcard *.workspace.sync360.co.nz is manually configured. As new client VPS servers are added, DNS updates are manual. Automate via Cloudflare DNS API. Scale ops
Architecture summary — v2 Two-server production deployment is live: control plane (161.97.74.128) + client runtime (89.116.28.191). The full 9-step provisioning engine (SSH + rsync + Caddy + docker compose + readiness probe + Brevo email) runs end-to-end. Eight service classes, two contract interfaces, and a driver-swap DI pattern keep dev and prod interchangeable via two env vars. The platform scales horizontally by adding server records — no code changes needed. Three layers remain unbuilt: billing (Stripe), skill packaging (the actual business moat), and channel activation (making the digital employee reachable). These are the next three milestones before a public launch.
